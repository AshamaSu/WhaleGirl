# 鲸鱼娘（WhaleGirl）业务需求说明书

> 文档性质：业务需求（BRD），面向项目负责人审核「要做什么、为什么做、怎么算做成」。
> 版本：v2（按「核心能力 / 外部能力」两层重构）。技术方案与施工顺序见 `docs/P2f-方案-插件化.md`。

## 1. 项目背景

聊天机器人产品普遍有三个问题：人设千篇一律、聊两轮就露出模板味；没有记忆，用户每次都要重复交代背景；能力全部耦合在一个工程里，加功能要改主流程，关功能又怕影响聊天。

本项目要做的，是一个「有记忆、有情绪、能自己找话题」的私人聊天体：她有自己的名字与语气，记得住主人说过的事，心情随对话起伏，会主动分享看到的内容，也能在群里被叫到时接话。

随着能力增加，结构问题开始显现：B站抓取、QQ 接入这类「外部能力」和「聊天本体」混在一起，导致核心越来越重、开关关不干净、出问题连带主链路。本期要做的是**把能力分成两层**：聊天本体永远在后台稳定运行，外部能力做成可安装、可启用、可卸载的独立单元。

## 2. 项目目标

**业务目标**

1. 让主人愿意长期聊：连续记忆、稳定人设、真实情绪，而不是一次性玩具。
2. 让聊天本体永不掉线：任何外部能力的安装、故障、卸载都不影响她回话。
3. 让能力可持续增加：新增一个外部能力（B站、QQ、小红书…）不改核心代码，按统一规范独立开发。
4. 让运行成本可控：单台 2G 云主机长期常驻，零 npm 依赖，能力按需安装。

**成功度量**

- 主人连续使用一周，无需重复自我介绍，她能主动提起此前的事。
- 卸载全部外部能力后，聊天、记忆、心情、后台运行完全正常。
- 新增一个同类外部能力，只需新建一个仓库 + 一份配置，不改核心代码。
- 云上连续运行 72 小时无重启、内存无持续增长。

## 3. 用户与角色

| 角色 | 说明 | 关注点 |
|---|---|---|
| 主人 | 唯一管理者与主要对话者 | 她记得住、语气像人、能自己找话题 |
| 群友 | 群聊中可能被她接话的成员 | 只在被叫到时被打扰，不被刷屏 |
| 维护者（同为主人） | 装/卸外部能力、改配置、看日志、做备份 | 装得上、关得掉、出事不影响聊天、数据不丢 |

## 4. 能力分层与范围

### 4.1 两层能力的定义

| 维度 | 核心能力 | 外部能力 |
|---|---|---|
| 定义 | 产品本体：对话、人格、记忆、情绪、管理 | 可插拔的功能单元：接入某个平台或提供某类专项能力 |
| 加载方式 | 随宿主启动，后台常驻 | 安装后按配置启用，重启生效 |
| 可关闭性 | 分两档：**不可关闭**（对话、记忆、心情、外部能力管理）、**可关不可卸**（管理端）；不可关闭能力的参数可在参数面板调整 | 可禁用、可卸载 |
| 是否可卸载 | 一律不可卸载 | 可安装、可卸载 |
| 故障影响 | 不可关闭的三项缺失即产品不成立；可关两项出问题只降级 | 只影响自身，必须不影响核心 |
| 数据位置 | 核心数据目录 | 各自独立的数据目录，卸载不删 |
| 举例 | 对话与人设、记忆、心情、系统管理、外部能力管理 | B站智能体、QQ群聊智能体、（未来）网页对话能力 |

**分层原则**：核心能力是「她是谁、她记得什么、她怎么说话、谁能管她」；外部能力是「她通过什么渠道接触外部世界」。外部能力只能调用核心提供的接口，不得反向修改核心。

### 4.2 核心能力清单

1. **核心对话与人设**：渠道无关的对话主链路、人设、分条表达、安全底线，以及核心内置工具（联网搜索、读取网页、记忆写入）。
2. **记忆**：短期对话、长期事实、衰减与置顶、时间线、备份恢复。
3. **心情**：每轮判定、数值与档位、语气注入、展示。
4. **系统管理**：宿主自带的网页管理端（对话 + 实时推送 + 设置 + 状态）、配置、日志、备份、部署运维、安全。
5. **外部能力管理**：外部能力的安装、启用、配置、隔离、版本握手与卸载。

### 4.3 外部能力清单

1. **B站智能体**：定时刷B站、筛选、产出报告、以她的口吻分享；并支持浏览记忆、按关注/历史选题、受控互动（赞/藏/币/三连）与有限度的留言回复。
2. **QQ群聊智能体**：接入 QQ 群与私聊，被叫到时接话，按群按人分别对待。

### 4.4 本期不做

- **外部形态的「网页对话能力」本期不建设**：网页对话与实时推送由核心自带的网页管理端承担（见 5.4）；未来若拆成外部能力，管理端仍保留为管理入口（见 6.3）。
- **主动搭话（speak-up）本期移出**：不在本期两类能力清单内，设计保留、不排期（2026-10-29 确认）。
- 多人 SaaS 与账号体系；语音转文字；Windows 微信桥；本地模型推理的服务端部署；多实例部署；插件市场、插件签名与沙箱；外部能力之间互相依赖。

## 5. 核心能力需求

### 5.1 核心对话与人设

**业务背景**：用户对聊天机器人的第一判断是「像不像人」，而不是功能多少。

**目标**：提供渠道无关、人设稳定、可分条表达、改人设免重启的对话主链路。

**用户故事**：作为主人，我希望不管从哪个入口找她，她都还是同一个人；说话短、有情绪、会分几条发。

**功能描述**

- 对话主链路与渠道无关：所有入口复用同一套处理，入口只负责收发，不含对话逻辑。
- 回复边生成边显示；按人设拆成多条气泡（默认最多 3 条），而不是一整段长文。
- 人设（称呼、语气、口头禅、回复长度、安全底线）以配置文件维护，改完下一轮生效，无需重启。
- 支持图片理解：用户发图，她能结合图片说话。
- 内置安全底线：拒绝色情、歧视、诅咒、暴力威胁类请求，简短拒绝、不说教。
- 每轮对话结束后，把本轮内容交给记忆与心情处理，但不阻塞回复。

**业务流程**：任一入口收到消息 → 归一化 → 组装人设 + 记忆 + 上下文 → 调用模型 → 流式/分条输出 → 回写记忆 → 触发心情判定。

**业务规则**

- 人设改动只影响之后的新对话，不改写历史记录。
- 单轮气泡数不得超过人设上限。
- 模型调用失败时给出明确提示，本轮不写入记忆。
- 核心对话不可关闭、不可卸载：即使所有外部能力都卸载，它必须完整可用。

**验收标准**

- 连续对话 10 轮，语气、称呼、句长稳定，不出现「作为一个AI」式表述。
- 修改人设文件后，下一轮生效，无需重启服务。
- 断网或模型超时，用户看到可读提示，恢复后可继续对话。
- 卸载全部外部能力后，对话功能与之前完全一致。

### 5.2 记忆

**业务背景**：没有记忆的陪伴是无效的；但无限记忆会让模型变慢、变贵、变糊涂。

**目标**：记得住重要的事，忘掉不重要的事，记忆边界对用户可见。

**用户故事**：作为主人，我希望她记得我的偏好和之前聊过的事；也希望我能看见她记住了什么、能删掉记错的。

**功能描述**

- 短期记忆：保存最近若干轮原始对话，超出窗口后自动压缩成摘要。
- 长期记忆：从对话中抽取「关于主人的事实」，带录入时间与强度。
- 事实强度随时间衰减，长期不被提及会自然淡出；手动置顶的事实永不衰减。
- 记忆时间线：可查看每条事实的时间、强度、来源，可置顶、可删除；每条事实带理论遗忘曲线参考（2026-10-30 增补）。
- 记忆参数可调（2026-10-30 增补）：衰减系数、遗忘阈值、容量、提示词注入量等 7 项进参数面板，改完热生效；参数存 `features.memory.params`（顶层 memory 段为兼容读法）。
- 备份与恢复：整包导出/导入，换机器或重装不丢。
- 她的自述（如定时分享）同样进入短期记忆，但不抽取成事实。

**业务流程**：对话结束 → 抽取事实 → 计算强度 → 下一轮把「相关事实 + 最近对话」注入人设 → 时间线可查可改。

**业务规则**

- 事实强度低于阈值即淘汰，置顶事实不参与衰减与淘汰。
- 自述内容只进短期记忆，不进事实层。
- 备份包含全部会话与事实；导入时跳过损坏条目并提示数量。
- 同一时刻只允许一个写入者修改同一会话的记忆，避免对话与后台任务互相覆盖。

**验收标准**

- 告诉她的偏好，隔天再问，她能自然提起。
- 时间线能看到该事实的时间与强度；置顶后不再衰减；删除后她不再提起。
- 导出 → 清空 → 导入，会话与事实条数一致。
- 后台分享与主人对话同时发生时，双方记录都不丢失。

### 5.3 心情

**业务背景**：情绪是「像人」的关键；但只增不减会很快失真。

**目标**：语气随互动自然起伏，并且用户能看见；心情呈现要像「她周围的天气变了」，而不是「她换了一个人」。

**用户故事**：作为主人，我希望她今天心情好不好能从语气里听出来，而不是永远一个调子。

**功能描述**

- 每轮对话后判定一次心情变化（小幅增减 + 一句话原因），复用主模型、输出极短，成本可忽略。
- 心情值 0–100，档位由数值推导，不维护两份真相。
- 当前心情与最近变化注入人设提示，影响语气。
- 五档表现（低落 / 有点丧 / 平静 / 心情不错 / 特别开心）：每档各有固定颜色、文字标签、光晕强度与 5 格档位点，档位由数值推导。
- **头像保持身份蓝**，情绪只体现在外环光晕与挂件（边框、底色、数值、曲线）上；只有「特别开心」档允许出现金色光，且只作为光。
- 挂件文案用第一人称心声（如「有点亮堂堂的」），不展示内部判定理由。
- 网页管理端提供挂件：当前数值、情绪标签、近 24 小时曲线、档位点。
- **会回落**：闲置一段时间后向基线（60）缓慢回归，避免只涨不跌钉在满值。
- **有回差**：档位切换留几点余量，数值在边界小幅抖动时不来回跳档。
- 每轮变化有上限（±8）：被夸/投机才会明显上升，被冒犯/敷衍才会明显下降，平常闲聊几乎不动。
- 她主动分享内容时也会小幅正向波动，同一轮只计一次。

**业务流程**：回复完成 → 判定增减 → 更新存储 → 管理端挂件刷新 → 下一轮注入。

**业务规则**

- 心情全局一份，不按会话区分。
- 判定失败或解析不出时按「本轮不变」处理，不阻塞对话。
- 同一轮多条气泡只产生一次心情变化。
- 心情为核心能力，不可关闭；基线、单轮变化上限、回差、回落速率等参数可在参数面板调整，改完热生效。
- **颜色只由数值推导**，模型只负责判断变化幅度与原因，不输出任何色值。
- **颜色不是唯一信息通道**：每个档位同时有文字标签与档位点，色弱/色盲也能读出状态。
- 金色是稀缺资源：只用于「特别开心」的光，不作大面积填充、不作文字色。
- 回落只发生在闲置时，不提醒、不推送；用户不主动看就感知不到。
- 过渡动画遵循系统「减少动态效果」偏好。

**验收标准**

- 连续聊 10 轮，挂件数值有涨有跌，语气可被感知；24 小时内至少出现 3 个档位。
- 数值 60 → 标签「平静」、品牌蓝、3 格档位点；数值 71 → 「心情不错」，数值文字可读。
- 上一档为 79 时到 81 不切档，到 83 才切到「特别开心」并出现金色光。
- 数值 90 闲置 6 小时后回落到约 78。
- 任意档位下，挂件文案都是第一人称心声，不出现「对方…」这类第三人称判定语。
- 灰阶（去色）下仍能靠文字标签与档位点分辨档位。
- 开启「减少动态效果」后呼吸动画不播放，金色光仍在。
- 参数面板改基线/单轮上限后行为按新参数变化，恢复默认后行为与原来一致；主动分享后小幅上升且同轮不重复加分。

### 5.4 系统管理

**业务背景**：这个产品是单人自维护的，必须有一个「打开就能看、改完就生效、出事能查」的管理入口，但不能让它成为系统的宿主——没人打开时，她也要照常运行。

**目标**：宿主启动即自带一个网页管理端，承担对话、实时推送、配置与状态查看；关掉它，后台一切照常。

**用户故事**：作为主人，我希望打开一个页面就能和她说话、看见她刚分享的内容、顺手改配置；作为维护者，我希望不打开页面时她也在正常生活和记录。

**功能描述**

- **网页管理端随宿主启动**：一个页面同时提供对话、记忆时间线、心情挂件、能力设置、状态与日志入口。
- **实时接收推送**：她的主动播报（B站分享等）实时出现在时间线，不需要刷新；**本页发起的对话**同样实时显示。其他会话（如群聊）里的往返回复不上本页，避免把群聊内容投影到主会话。能力状态变化不实时推送，见下条。
- **配置页**：按能力声明的表单自动渲染——**核心能力与外部能力同一套形状**，心情等内置开关也在页面上有入口；保存即生效（无需重启的项立即生效，需重启的明确提示）。
- **状态与日志**：各能力启用/关闭/拒载原因、模型与人设信息、最近错误；打开状态页时可见（不承诺实时推送状态事件）。
- **备份与恢复**：一键导出/导入记忆。
- **对话展示范围 = 记忆窗口**：打开时加载最近对话，更早内容不再展示；页面不保存本地聊天历史。
- **可整体关闭**：关闭后不提供页面与实时推送，但对话、记忆、心情、外部能力调度照常。

**业务流程**：启动宿主 → 管理端可用 → 打开页面拉取最近对话并建立实时通道 → 新消息实时出现 → 关闭页面不影响后台。

**业务规则**

- 管理端是核心内置界面，不属于可插拔的外部能力；本期不提供外部形态的网页对话能力。
- 管理端固定使用主会话，不做多会话切换。
- 默认只监听本机；公网访问必须有访问控制——已落地：`.env` 设置 `WG_ADMIN_TOKEN`，`/login` 登录换 Cookie 会话；未登录访客只能看（记忆/调参/插件三页只读）与聊天，其余写操作一律 401。
- 管理端关闭时，后台任务与记录不得中断；**关闭后仍必须能恢复**——通过修改配置或命令行重新开启，不依赖页面自身（否则关掉页面就再也打不开）。
- 外部能力的安装与启停在页面不可用时也可通过命令行完成。

**验收标准**

- 启动后无需额外安装，打开页面即可对话，并看到最近对话。
- B站分享等主动播报能实时出现在时间线，无需刷新；能力被拒载时在状态页可见原因。
- 关闭管理端后，可用配置文件或命令行重新开启，不需要手工改代码。
- 在配置页改一个参数并保存，行为按预期变化（或明确提示需重启）。
- 关闭管理端后，通过其他渠道对话、记忆写入、心情变化、后台分享照常发生。
- 重新打开管理端，只看到记忆窗口内的内容；更早的事靠对话问答。

### 5.5 外部能力管理

**业务背景**：外部能力越多，越不能让它们污染核心；装、启、配、卸必须是一套统一动作。

**目标**：外部能力像 App 一样安装与卸载；核心只负责加载与隔离。

**用户故事**：作为维护者，我希望装一个能力只是「放进去 + 打开开关」，卸载后核心照常跑、数据还在；作为主人，我希望任何外部能力坏掉都不影响聊天。

**功能描述**

- 能力清单化：每个外部能力是独立仓库，含清单（名称、版本、所需核心接口、配置表单定义）。
- 安装与卸载：命令行工具支持安装（远程仓库或本地目录）、卸载、更新、查看已装/已启用/缺失。
- 启用与配置：安装后在管理端按表单配置并启用；未安装 = 不存在，未启用 = 不加载。
- 失败隔离：清单损坏、版本不匹配、依赖缺失、启动报错，都只跳过该能力并给出原因。
- 能力只能申请它声明的核心接口，多给不给、少给拒载。
- 能力的路由、工具、配置、数据均带命名空间，互不干扰，也不能覆盖核心接口。
- 能力数据卸载不删；能力配置随能力走。

**业务流程（安装）**：获取能力仓库 → 安装到能力目录 → 校验清单与版本 → 管理端出现该能力 → 填写配置并启用 → 重启生效 → 日志与状态显示启用情况。

**业务规则**

- 安装能力等于在本机运行其代码：只安装自己写的或读过源码的；安装时给出提醒。
- 不做运行时热插拔：安装、卸载、升级后重启生效。
- 外部能力之间禁止互相依赖与互相读取数据。
- 升级核心时，旧能力要么继续可用，要么被明确拒载并提示升级方式，不能静默失效。
- 任何能力的加载失败都不影响聊天主链路与后台运行。

**验收标准**

- 全新部署不安装任何能力时，聊天、记忆、心情、管理端完整可用。
- 安装B站智能体并启用后，分享行为与拆分前一致，历史记录连续（不重复推荐、额度不重置）。
- 删除能力目录后服务正常启动，管理端提示「已配置但未安装」。
- 故意写错清单或缺声明时，该能力被拒载，其余能力与聊天不受影响。
- 关闭某能力后，其定时任务、推送、工具、路由全部停止，无残留。

## 6. 外部能力需求

### 6.1 B站智能体

**业务背景**：她是「会自己找乐子」的角色，而不是只会接话的应答机。

**目标**：在合适的时间自己刷B站，挑一条值得看的，用自己的口吻分享；并且记得自己看过什么、能按主人的口味找、在受控前提下点赞/收藏/投币、看懂并有限度地回应留言。

**用户故事**：

- 作为主人，我希望她偶尔主动推荐一条视频，并说得出为什么值得看。
- 作为主人，我问「今天你在B站看了些什么」时，她应该答得上来，而不是说「我哪看得到呀」。
- 作为主人，我希望她选题时参考我关注的人和我最近在看什么。
- 作为主人，我看到好视频想让她「三连一下」时，她能执行并告诉我结果。
- 作为主人，我希望她知道谁回复了我，并且只在我说「回他」时才开口。

**功能描述**

- 按设定间隔自动触发（默认 180 分钟，可配），仅在活跃时段内运行，每日有轮数上限。
- 拉取热门/关注UP的最新视频，读取标题、简介、字幕；**拿不到字幕的视频按跳过处理**（不降级、不重试），换下一条。
- 由独立的「子代理」流程评估筛选，产出客观报告（理由、播放量、链接），不直接对主人说话。
- 报告落盘归档；再由主人设生成 1–3 条口语化推荐，经统一播报通道推送。
- 已推荐过的视频不重复推荐；支持手动触发一轮。
- **记得看过什么**：每轮看过/挑中的视频写入结构化历史（时间、标题、UP、链接、来源、动作），并在对话里可被引用；问「今天看了什么」时能说出具体条目。
- **按主人偏好选题**：可配置候选来源——热门、关注 UP 的最新动态、主人近期观看相关内容；来源可单独开关。
- **受控互动**：点赞、收藏、投币、一键三连；默认全部关闭，开启后仅按主人明确指令执行，有每日上限与重复保护，投币需单独确认（不可撤销）。
- **留言与回复**：能读取「回复我的」「@我的」与视频下的楼中楼；回复默认关闭，开启后只对主人或白名单对象、逐条指令执行。
- **朋友关注管理**（2026-10-30 增补）：主人在网页端提交朋友的 B站 MID 即执行关注、移除即取关，计入每日关注额度；已加入【特别关注】分组的账号禁止网页端取关（去B站 App 操作），特别关注分组的加入本身由主人在B站侧手动维护。
- **特别关注优先选题**（2026-10-30 增补）：特别关注 UP 的最新投稿每轮注入选题候选并置优先级；抓取失败只跳过该来源，不阻塞轮次。
- **概念记忆**（2026-10-30 增补）：浏览轮结束后把「本轮看了什么」压缩成一条概念总结写进宿主记忆事实层（source=bili），随标准衰减曲线自然淡忘；报告全文仍不进事实层。
- **对话查询她的B站动态**（2026-10-30 增补）：主对话注册只读查询工具（浏览/关注/回复三类），仅当主人明确问起时调用，回答以本地留存记录为准。
- **接口选型原则**：本项目不具备B站开放平台企业资质，官方开放接口不可用。公开能力走公开接口；账号相关能力（观看历史、关注、互动、消息）使用登录态网页接口，统一收在一个适配层里，可整体关闭并降级为公开浏览，不影响聊天。

**业务流程（浏览分享）**：定时器唤醒 → 判断活跃时段与额度 → 拉取候选（热门 / 关注动态 / 观看历史）→ 子代理评估 → 报告落盘 → 人设改写口吻 → 分条推送 → 记录已推荐与浏览历史。

**业务流程（互动）**：主人指令（或自动开关命中）→ 校验开关 / 每日额度 / 是否已操作 → 调用官方接口 → 记录动作与结果 → 回报成功或失败原因。

**业务流程（留言回复）**：拉取「回复我的 / @我的」→ 汇总摘要 → 主人说「回他：…」→ 白名单与安全底线校验 → 发评论 → 记录结果，失败不重试。

**业务规则**

- 非活跃时段、超出每日额度、上一轮未结束时一律跳过，不排队补跑。
- 拿不到字幕的视频按跳过处理，不重试、不报错，轮次继续。
- 推荐内容必须带视频链接。
- 报告全文只归档，不进记忆事实层；她说过的那几句话进短期记忆。
- 可整体禁用或卸载；禁用后不产生任何定时任务与推送，卸载后聊天照常。
- **只读默认开、写入默认关**：点赞/收藏/投币/三连/回复评论都属于写操作，必须单独开启，且每次由主人明确指令触发。
- **不可逆要说清**：投币不可撤销、评论公开可见；执行前提示，执行后如实回报成功或失败原因（未登录、硬币不足、风控、已操作过）。
- **重复保护与额度**：同一条视频的同一动作只执行一次；写操作有每日上限；超限直接拒绝并说明。
- **隐私**：观看历史与关注列表属于隐私数据，只在本机参与选题，不写入报告、不播报、不外传。
- **账号标识只放环境变量**：主人的B站 mid、QQ 号等身份信息写进 `.env`（如 `WG_BILI_MID`），不进 `config.json`——配置可能被分享或误提交，账号不该跟着走。
- **接口降级**：登录态失效（cookie 过期、风控）或某个网页接口改版时，只降级对应能力并提示原因，公开浏览照常；任何 B站相关故障都不影响聊天与记忆。
- **回复克制**：只回复主人或白名单对象，逐条指令；不自动回复、不批量、不在同一楼层重复发言。

**验收标准**

- 开启后能在活跃时段内自动产出一轮分享，管理端时间线可见 1–3 条口语化推荐，带链接。
- 当天超过额度后不再自动触发；手动触发仍可用。
- 无字幕视频不导致整轮失败，日志可见跳过原因。
- 禁用后不再有任何推送，聊天与其他能力不受影响。
- 问「今天你在B站看了些什么」，能说出当天至少 1 条标题与一句内容概括。
- 开启个性化来源后，能看到本轮候选来自热门/关注/历史中的哪一类；关闭后回落热门，行为与现在一致。
- 互动未开启时不产生任何写请求；开启后按指令执行，结果可读，重复指令返回「已经点过了」，超限被拒。
- 回复未开启时无法发出任何评论；开启后只对白名单对象生效，且每条都需要明确指令。
- 任意外部接口故障时，浏览自动降级，聊天、记忆、心情不受影响。

**细分能力一览**

| 细分能力 | 默认状态 | 触发方式 | 关键限制 | 对应验收 |
|---|---|---|---|---|
| 浏览记忆（她看过什么） | 开 | 每轮自动记录 | 只记她自己的浏览行为；历史仅本机 | 问「今天看了什么」能答出具体条目 |
| 个性化选题 | 关 | 每轮（开启后） | 只读；来源可单独开关；隐私不外泄 | 候选来源可见；关闭回落热门 |
| 互动（赞/藏/币/三连） | 关 | 主人明确指令 | 每日上限；同条同动作幂等；投币不可逆 | 结果可读；重复返回已点过；超限拒绝 |
| 留言与回复 | 读开 / 写关 | 读：按需汇总；写：主人逐条指令 | 仅主人或白名单；限频；不自动回复 | 未开启无法发出；开启后仅白名单生效 |
| 朋友关注管理 | 开 | 网页端提交即执行 | 特别关注组禁止网页取关；每日关注/取关额度 | 提交即关注；移除即取关；特别关注拒绝并提示去 App |
| 特别关注优先选题 | 开 | 每轮（有特别关注时） | 只读；单 UP 失败跳过不阻塞 | 候选里能看到特别关注 UP 的新投稿且优先入选 |
| 概念记忆 | 开 | 每轮入选后自动写 1 条 | source=bili；随标准衰减；日上限随轮数额度 | 隔天问起能提起；长期不提自然淡忘 |
| 对话查询B站动态 | 开 | 主人明确问起时模型调工具 | 只读本地留存；不问不查 | 问「看了/关注了/回复了什么」能答出记录 |

### 6.2 QQ群聊智能体

**业务背景**：主人和群友主要活跃在群里；她需要在群里像一个正常群友一样存在。

**目标**：被叫到时接话，未被叫到时保持安静；不同群、不同人分别对待。

**用户故事**：作为群友，我希望@她时她真的回我，而不是对每条消息都插嘴；作为主人，我希望她只在白名单群里出现。

**功能描述**

- 通过 OneBot 11 协议接入 QQ（NapCat 等实现），接收群消息与私聊消息。
- 触发条件：被@、被回复、被叫名字；其余消息只读不接。
- 连续对话窗口（默认 6 分钟）内可自然接话，超时回到「只应答」状态。
- 群白名单：非白名单群完全静默。
- 不同群各自独立会话与记忆；群内按发言人分别记录「关于这个人的小事」。
- 回复回到原群/原会话，必要时@提问者；长内容可分条发送。
- 群内管理指令：开关能力、清空记忆、静默等；**仅主人账号可执行**，其他成员发送的指令按普通消息处理或静默忽略。

**业务流程**：群消息到达 → 归一化（群/人/内容/是否@）→ 白名单与去重 → 判定是否接话 → 写入该群会话 → 生成回复 → 回到原群（必要时@）。

**业务规则**

- 同一消息只处理一次（按消息 id 去重）。
- 系统通知、公众号推送类消息一律不接。
- 群聊记忆与主会话不串；不同群记忆互不可见。
- 回复失败只记日志，不影响其他群与核心对话。
- 可整体禁用或卸载；禁用后不在任何群出现。

**验收标准**

- 测试群内@她 3 轮内均有回复；非白名单群完全静默。
- 未被@的连续闲聊不触发回复；6 分钟窗口内可自然接话。
- 两个群同时对话，各自上下文与记忆不串。
- 断开 QQ 连接后，管理端聊天不受影响。

### 6.3 网页对话能力（本期不建设，仅记录边界）

**定位**：未来可把「网页对话」做成一个外部能力，与核心自带的网页管理端解耦。

**本期决策**：不建设。现阶段的网页对话与实时推送全部由核心的网页管理端承担（5.4）。

**边界约定**：若将来建设该外部能力，须满足——复用核心对话接口，不复制对话逻辑；只作为展示与输入终端；推送仍由核心统一分发；管理端保留为管理入口（配置、状态、日志），两者可同时存在但不得各自维护一份记忆。

## 7. 端到端业务场景

**场景一：普通的一天**

主人早上打开管理端聊几句 → 她记下今天的安排 → 中午在群里被@时接话 → 下午到活跃时段，她刷B站并分享 → 管理端时间线实时出现那几条推荐 → 主人晚上追问视频内容，她答得上来。

**场景二：给新机器装外部能力**

维护者新开云服务器 → 注入密钥 → 启动核心（此时只有对话、记忆、心情、管理端）→ 安装B站智能体 → 管理端填配置并启用 → 重启 → 状态显示已启用，当天开始正常分享。

**场景三：不开管理端**

主人出差只用 QQ → 不打开管理端 → 群聊、记忆、心情、B站分享照常 → 回来打开管理端，最近对话与分享都在，更早的靠她口述。

**场景四：外部能力出问题**

某次升级后B站智能体清单不兼容 → 服务正常启动，状态提示「需要核心版本 n，当前 m」→ 聊天完全不受影响 → 维护者更新或回退能力版本后重启恢复。

**场景五：卸载全部外部能力**

主人暂时不想让她刷B站、也不接QQ → 卸载两个外部能力 → 核心照常运行：能聊、能记、有心情、管理端可看 → 数据目录保留，重新装回后历史连续。

## 8. 全局业务规则

1. **分层不越界**：核心能力不可卸载、不可缺失；外部能力只能调用核心接口，不得反向修改核心。
2. **开关即隔离**：外部能力未安装等于不存在，未启用等于不加载；关闭后不产生定时任务、推送、工具与路由。
3. **故障不外溢**：任何外部能力初始化或运行失败，只记日志与状态，聊天主链路必须完整可用。
4. **数据主权**：每个外部能力的数据只存在自己的目录，能力之间不互访；卸载不删数据。
5. **记忆即边界**：用户能看到的历史不超过她记得的范围；展示层不制造「虚假记忆」。
6. **人设一致**：所有出口（管理端、QQ、主动分享）使用同一人设与同一套表达规则。
7. **不被骚扰**：主动行为受时段、冷却、频率约束；群聊未被叫到不插嘴。
8. **安全底线**：拒绝色情、歧视、诅咒、暴力威胁；密钥只走环境变量；管理端默认不暴露公网。
9. **可回退**：外部能力升级失败可回退上一版本；数据迁移前的旧目录保留可回滚。

## 13. 术语

| 术语 | 含义 |
|---|---|
| 核心能力 | 产品本体能力，随宿主启动常驻，不可卸载 |
| 外部能力 | 可安装、可禁用、可卸载的功能单元，故障不影响核心 |
| 宿主 / 核心 | 承载对话、记忆、心情、管理与能力加载的本体 |
| 网页管理端 | 宿主自带的网页界面：对话、实时推送、设置、状态、备份 |
| 会话 | 一段独立上下文的对话；主会话固定一个，QQ 按群/私聊各自独立 |
| 播报 | 她主动说出的话（分享等），与「回复某人」区分 |
| 记忆窗口 | 她当前能直接看到的最近对话范围，也是管理端展示范围 |
| 活跃时段 | 允许她主动行为的时间段 |
