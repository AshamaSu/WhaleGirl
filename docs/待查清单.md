## INC-001：工具调用以 DSML 文本返回，脏文本落盘

**发现时间**：2026-10-29 15:26（本地时间）

**发现场景**：M4 E2E 的 T10（关闭能力开关）期间。当时把 `features.bili.enabled` 改为 `false` 后，旧实例的路由尚未撤销（T10 已单独记录），`POST /api/features/bili/run` 仍返回 `202` 并跑完了一轮。

**现象**：报告不是正常的中文推荐，而是模型原始的工具调用文本：

```
## 2026-10-29 15:26 · 手动
"鲸鲸，跑起来吧"是用 AI 生成工具做的赛博朋克改编短片，这个有技术看点。我看下评论确认成片质量。

<｜｜DSML｜｜ calls>
<｜｜DSML｜｜ invoke name="bili_comments">
<｜｜DSML｜｜ parameter name="bvid" string="true">BV1Qwx56bEig</｜｜DSML｜｜ parameter>
<｜｜DSML｜｜ parameter name="ps" string="false">10</｜｜DSML｜｜ parameter>
</｜｜DSML｜｜ invoke>
</｜｜DSML｜｜ calls>
```

同轮 `lastResult = { ok: true, trigger: 'manual', picked: [], error: '' }`，`picked` 为 0 但状态仍是成功。

**技术判断**：`<｜｜DSML｜｜ …>` 是 DeepSeek 的工具调用文本标记（DSML），等价于一次 `bili_comments` 调用。我们的链路只认结构化字段：`src/llm.js:129-133` 从 `delta.tool_calls` 取调用，`src/agent.js:97-108` 只有收到 `tool_calls` 事件才执行工具；标记落在 `content` 里，于是被当成最终文本返回并落盘。

**与能力开关的关系**：无因果关系。开关只影响 `features` 宿主的启停（清定时器、撤路由），不改变模型请求形状。当日 3 次正常、1 次异常，异常那轮恰好发生在关闭窗口内，但没有导致该格式的机制。

**影响**：

1. 该轮工具未执行（本该看评论），报告内容不可读，`picked=0`；
2. 脏文本同时写进 `data/bili/out/` 与 `data/bili/digest/`，会污染归档与后续翻阅；
3. 若开启播报，这段标记会被念给用户；
4. `ok:true` 掩盖了失败，验收时容易误判通过。

**当前处置（2026-10-29）**：

- 原始文件已备份：`backups/2026-10-29-dsml/out-2026-10-29.md`、`backups/2026-10-29-dsml/digest-2026-10.md`（含完整异常段）。
- 正式数据已清理：`data/bili/out/2026-10-29.md` 删除 15:26 段（保留 15:11、15:15 两轮）；`data/bili/digest/2026-10.md` 删除对应段落。已校验两份文件均无 `DSML` 残留。
- 代码未改，等复现后再定方案。

**复现条件 / 已知频率**：当日 4 轮中出现 1 次（15:11 ✅ / 15:15 ✅ / 15:26 ❌ / 10-27 ✅）。触发上下文不完全明确，可能与模型/网关偶发把工具调用写成文本有关。

**再次出现时要收集**：

1. 完整报告段（`out/` 原文）与同轮 `state.json`；
2. `logs/` 中该轮相关行（含模型名、finish_reason）；
3. 当时的 `llm.js` 原始流片段（如能加临时日志，记录 `delta` 是否含 `tool_calls`）；
4. provider（deepseek / zhipu / custom）与模型名，判断是否集中在某一路。

**修复方向（二选一，未决）**：

- **A. 兜底拒绝**：在 `src/agent.js` 的 final 分支检测 `</?｜｜DSML｜｜`（以及 `<tool_call` 一类残留），命中即抛错，本轮 `ok:false`、不落盘、不播报、不进 digest；配一条用本事件真实文本做夹具的单测。放 `agent.js` 而非 bili，因为将来其他用工具的插件也会踩。
- **B. 真正解析**：在 `src/llm.js` 把 content 里的 DSML 解析回 `tool_calls`（需处理流式分片、`string="true|false"` 类型、转义），恢复该轮能力。

建议顺序：先 A 止血，B 视复现频率再投入。

**关联**：M4 E2E 用例 T03（报告格式）、T09（异常处理）；与 P2f 插件化无直接关系。
