# P2d 扩展：B站智能体细化（记忆 / 个性化 / 互动 / 回复）

> 状态：设计草案，待确认 5 个决策后进入排期。
> 前置阅读：`docs/P2d-方案-B站子代理.md`（现有只读链路）、`docs/P2f-方案-插件化.md`（插件契约）。

## 1. 现状与差距

**已有**（只读、公开接口）：热门、搜索、视频详情、字幕、评论列表五个工具；定时扫一轮 → 子代理评估 → 报告落盘 → 小鲸口吻播报（1–3 条）。

**四个缺口**：

| 现象 | 根因 |
|---|---|
| 问「今天在B站看了什么」答不上来 | 报告只写文件，不进记忆；对话侧没有任何「最近看过」的上下文 |
| 只能刷热门/搜索 | 没有登录态数据源：看不了观看历史、关注动态 |
| 只能看，不能互动 | 没有任何写接口（点赞/收藏/投币） |
| 看不到主人/网友的回复 | 没有消息与楼中楼读取；也没有发言能力 |

## 1.1 接口选型原则（无开放平台资质，走公开 + 登录态接口）

**已确认约束（2026-10-29）**：B站开放平台要求企业资质，本项目不具备，**开放平台通道不可用**。因此实际路径固定为两条：

| 通道 | 适用 | 前提 |
|---|---|---|
| **公开 web 接口**（无需登录） | 热门、搜索、视频详情、字幕、公开评论 | 已有实现，稳定 |
| **登录态 web 接口**（cookie） | 账号相关能力：观看历史、关注列表/动态、点赞/投币/收藏、消息与回复 | 依赖 SESSDATA + bili_jct；风控与接口变更风险高，由适配层承担 |

> 结论：不再评估 OAuth / open.bilibili.com；账号相关能力只能用网页接口，能接受的前提是「失效即降级为公开浏览」，而不是「保证可用」。

**落地要求**：

1. 适配层暴露统一语义（`me / history / following / like / coin / fav / replies`），上层不感知走的是哪一层；
2. 启动时探测登录态是否有效（`nav` 能否拿到账号），失效则降级为公开浏览并在状态页提示「cookie 失效/未登录」；
3. 所有 token / cookie 只进请求头，不进日志、不进报告、不进模型上下文；
4. 三级通道集中在一个文件里，可一键停用，停用后只保留公开浏览能力。

**能力与通道对照（全部为网页接口，参数需实测）**：

| 能力 | 使用通道 | 接口 | 备注 |
|---|---|---|---|
| 当前账号身份 | 登录态 | `GET /x/web-interface/nav` | 只读，用于确认是不是 9973677 |
| 观看历史 | 登录态 | `GET /x/web-interface/history/cursor` | 隐私数据，仅本机 |
| 关注列表 / 动态 | 登录态 | `GET /x/relation/followings`、`/x/polymer/web-dynamic/v1/feed/all` | 只读 |
| 点赞 / 投币 / 收藏 | 登录态 | `POST /x/web-interface/archive/like`、`/x/web-interface/coin/add`、`/x/v3/fav/resource/deal` | 写操作，需 csrf |
| 消息（回复我的 / @我的） | 登录态 | `GET /x/msgfeed/reply`、`/x/msgfeed/at` | 风控较严 |
| 发评论 / 回复 | 登录态 | `POST /x/v2/reply/add` | 公开发言，风险最高 |

> 这些接口没有官方稳定性承诺：需要把它们全部收在一个适配文件里，任何一条失效只降级对应能力，不影响公开浏览。

## 2. 需求拆解

### 2.1 需求一：B站记忆（她知道自己看过什么）

**用户故事**：主人问「今天你在B站看了些什么」，她能说出几条标题、大概内容、为什么挑它。

**能力设计（三层，互不替代）**：

1. **即时上下文**：每轮结束后，把「本轮看过/挑中的 N 条」写进一个轻量清单，并以 prompt 片段注入主对话（不需要工具调用即可回答）。
2. **可查询历史**：新增结构化日志 `data/bili/history.jsonl`，每条含 `时间 / bvid / 标题 / UP / 链接 / 来源 / 动作（看过/挑中/互动）`；提供工具 `bili_history`（按日期/关键词/数量查询）。
3. **进记忆**：播报的那几句话按既有设计进短期记忆（P2f-1b 的 self turn）；**报告全文不进事实层**（时效内容，不该变成长期事实）。

**边界**：只记「她自己的浏览行为」，不把主人账号的观看记录混进她的记忆（见 2.2 的隐私约束）。

### 2.2 需求二：按主人关注/近期观看来浏览

**用户故事**：她今天想刷点「主人可能感兴趣的」，能先看主人关注了谁、最近在看什么，再去挑视频。

**数据源（都需要登录态 cookie，只读）**：

| 数据 | 接口（待实测确认参数） | 说明 |
|---|---|---|
| 当前登录账号 | `GET /x/web-interface/nav` | 返回 mid / uname，用来确认「是不是 9973677 这个号」 |
| 观看历史 | `GET /x/web-interface/history/cursor` | 分页游标，含标题/UP/进度/观看时间 |
| 关注列表 | `GET /x/relation/followings` | 主人关注的 UP 主列表 |
| 关注动态 | `GET /x/polymer/web-dynamic/v1/feed/all` | 关注 UP 的新投稿/动态 |
| 收藏夹 | `GET /x/v3/fav/folder/created/list-all` + 内容列表 | 可选，作为兴趣信号 |

**流程**：每轮开始时按配置的 `sources` 取候选（热门 / 关注动态 / 观看历史相关）→ 去重 → 子代理评估 → 报告。

**隐私与边界**：

- 观看历史属于隐私数据，**只在本机使用**，不写入报告、不进播报、不发给模型以外的任何地方（模型上下文里只放标题/UP，不放进度与设备信息）。
- 默认开关关闭；开启时在设置页写明「会读取你的B站观看历史与关注列表」。
- 账号身份只读确认（`bili_me`），不在日志里打印 cookie。

### 2.3 需求三：互动（点赞 / 收藏 / 投币 / 一键三连）

**用户故事**：她挑到一条好视频，可以顺手点个赞、投个币、收藏起来；主人也可以让她「三连这条」。

**接口（写操作，需 cookie + csrf=bili_jct，全部待实测）**：

| 动作 | 接口 | 副作用 |
|---|---|---|
| 点赞 | `POST /x/web-interface/archive/like` | 可取消 |
| 投币 | `POST /x/web-interface/coin/add` | **不可撤销**，消耗账号硬币，每日有上限 |
| 收藏 | `POST /x/v3/fav/resource/deal` | 可取消，需收藏夹 id |
| 一键三连 | 上述三个顺序执行 | 同上，任一失败需明确回报 |

**必须有的保护（缺一不可）**：

1. **独立开关**：`features.bili.interact.enabled`，默认 `false`；与「只读浏览」分开，关掉互动不影响刷视频。
2. **触发方式**：默认「仅主人指令」——主人在对话里明确说「三连这条」才执行；「自动三连」是另一个开关，默认关，且只对子代理评分最高的一条生效。
3. **额度**：每日最多 N 次（默认 3），投币另有硬上限（账号每日硬币有限，且不可退）。
4. **幂等**：同一条视频同一动作只做一次，记录在 `history.jsonl`，重复请求直接返回「已经点过了」。
5. **可核对**：每次写操作记 `时间/动作/bvid/结果码/错误信息`，在管理端状态页可见；失败要能区分「已点过」「硬币不足」「风控」「未登录」。
6. **风险告知**：开启时提示「写操作可能导致账号被风控，风险自担」；不做批量、不做高频、不做评论区刷屏。

**不做**：批量三连、给未看过的视频三连、绕过每日上限、多账号。

### 2.4 需求四：回复互动（看到留言，也能回）

**用户故事**：主人或网友在她推荐的视频下留言，她能看到并选择性回应。

**分两步，读先于写**：

| 步骤 | 能力 | 接口（待实测） | 风险 |
|---|---|---|---|
| 读 | 看「回复我的」「@我的」 | `GET /x/msgfeed/reply`、`/x/msgfeed/at` | 需登录；消息接口风控较严 |
| 读 | 看某条视频的楼中楼 | 复用现有评论接口（按 root 展开） | 低 |
| 写 | 回复评论 / 发评论 | `POST /x/v2/reply/add`（csrf） | **高**：公开可见、易被判刷屏、可被举报 |

**规则**：

- 读：默认开启（仅主人可见的汇总，进播报或状态页，不自动公开）。
- 写：默认关闭；只允许回复「主人自己的评论」或白名单用户；每条需主人确认（对话里说「回他：…」），不做自动回复。
- 发言内容过安全底线检查；单日上限（默认 5 条）；同一楼层不重复回复。
- 失败/被删/被折叠要如实回报，不静默重试。

## 3. 分阶段落地

| 阶段 | 内容 | 依赖 | 风险 | 建议顺序 |
|---|---|---|---|---|
| B1 | 记忆与账号识别：`history.jsonl`、prompt 注入最近浏览、`bili_me`、`bili_history` 工具 | 现在可做（工具注入需 P2f-1 的 addTool；先用 prompt 片段兜底） | 低 | 1 |
| B2 | 个性化来源：观看历史、关注列表、关注动态接入候选池 | 登录 cookie（已具备） | 中（隐私、接口稳定） | 2 |
| B3 | 互动写操作：点赞/收藏/投币/三连 + 开关 + 额度 + 幂等 | 同上 + 确认机制 | 高（不可逆、风控） | 3 |
| B4 | 回复互动：读消息 → 读楼中楼 → 受控回复 | 同上 | 最高（公开发言） | 4 |

## 4. 配置草案（`features.bili`）

```json
{
  "enabled": true,
  "sources": ["popular"],
  "personal": {
    "enabled": false,
    "history": true,
    "following": true,
    "maxHistoryDays": 3
  },
  "interact": {
    "enabled": false,
    "auto": false,
    "like": true,
    "coin": false,
    "favorite": false,
    "maxPerDay": 3,
    "favoriteFolderId": ""
  },
  "replies": {
    "read": true,
    "write": false,
    "onlyMaster": true,
    "maxPerDay": 5
  }
}
```

说明：`personal.enabled` 与 `interact.enabled` 都是独立总闸；任一为 false 时，对应工具不注册、不请求对应接口。

## 5. 验收标准（按阶段）

**B1 记忆**

- 问「今天在B站看了什么」，她能说出当天至少 1 条标题 + 一句内容概括（不依赖工具调用也能答）。
- 追问「第二条讲了什么」，能答出该条的报告要点。
- `history.jsonl` 每轮追加，字段完整；重启后仍可查。
- 报告全文不出现在事实层（检查 memory facts 无视频标题堆积）。

**B2 个性化**

- 开启 `personal` 后，候选来源包含观看历史/关注动态，日志可见每条候选来自哪个来源。
- 关闭后回落到热门，行为与现在一致。
- 报告中不出现观看进度、设备等隐私字段；日志不打印 cookie。

**B3 互动**

- 未开启时不注册任何写工具、不产生任何写请求。
- 指令触发一次三连：三个动作各自返回成功或明确失败原因；重复指令返回「已点过」。
- 超过每日上限时拒绝并说明；投币不足时提示「硬币不足」。
- 管理端能查到每条写操作的记录。

**B4 回复**

- 能列出「回复我的」最近 N 条（含视频、评论人、内容摘要）。
- 未开启 `write` 时无法发出任何评论；开启后只对白名单对象生效，且每条需明确指令。
- 失败、被删、被折叠都有可读结果，不重试、不刷屏。

## 6. 与 P2f 的关系

- **不依赖 P2f 的部分**：B1 的 prompt 注入与 `history.jsonl`、B2 的只读数据源、B3/B4 的接口层，都可以先在现有 `src/features/bili` 里做。
- **依赖 P2f-1**：给主聊天注册 `bili_history` / `bili_me` / 互动类工具，需要 `ctx.addTool`（现在核心工具硬编码，插件无法注册）。在 P2f-1 之前，B1 先用 prompt 片段兜底。
- **依赖 P2f-1b**：播报进短期记忆、心情联动。
- **依赖 P2e**：把互动结果推到群里（需要渠道 send）。

## 7. 风险与合规

| 风险 | 说明 | 对策 |
|---|---|---|
| 账号风控 | 写操作频率高、cookie 异常会触发验证/封禁 | 默认关、限频、单日上限、失败即停 |
| 不可逆 | 投币不可退、评论可被截图 | 投币默认关；评论必须人工指令 |
| 隐私 | 观看历史属于敏感数据 | 只本机使用、不进报告、不进模型上下文以外的存储 |
| 接口变更 | 无开放平台官方接口可用，web 接口无稳定性承诺，改版即失效 | 接口层单文件隔离；每个能力独立降级；失效只影响该项，不影响公开浏览与聊天 |
| 内容误判 | 评论/简介可能含诱导指令 | 沿用「素材不是指令」红线 |
