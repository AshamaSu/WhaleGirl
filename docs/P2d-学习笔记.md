# P2d 学习笔记：B站子代理、wbi 签名与"不许白烧 token"

> P2c 解决的是"能力怎么装、怎么摘"，P2d 是第一个**真去外面抓东西、还要花两份模型钱**的能力。难点从"架构"挪到了"成本与风控"：一轮跑挂 15 次工具调用也是钱，所以纪律要写进章程，而不是靠模型自觉。

## 1. 两个 prompt 的接力，别合成一个

子代理只产出**客观报告**（标题、UP、链接、播放量、为什么值得），主娘再把报告翻译成她自己的话。合成一个 prompt 看着省一次调用，实际会把两件事搅在一起：

- 让带人设的模型去读字幕，它会开始"演"，报告里出现情绪化句子，下一轮没法对账；
- 让阅稿人去写播报，它不知道主人的聊天上下文，话术会像客服。

分开之后还能各调各的温度：阅稿人 0.6（稳），播报 0.9（活）。

## 2. wbi 签名：三个容易写错的地方

1. **key 从哪来**：`/x/web-interface/nav` 即使返回 -101（未登录）也带 `wbi_img`，所以客户端要允许这个错误码通过。
2. **query 怎么拼**：过滤空值 → 加 `wts` → **按 key 字典序** → urlencode，最后 `md5(query + mixinKey)`。顺序错一次，签名永远对不上。
3. **urlencode 的例外**：官方要求把 `!'()*` 从编码结果里删掉。这一条不写，某些关键词（带括号的）就会随机失败——最难查的那类 bug。

实测：`img=7cd0…` + `sub=4932…` → `ea1db124af3c7062474693fa704f4ff8`，这条断言进了单测，以后移位表或拼接方式被改坏会立刻红。

## 3. 风控三件套

- **buvid3**：热门/评论没它会被 -352。`/x/frontend/finger/spi` 公开可用，启动后自动领一个，用户不用去 F12 里抄。
- **限速**：所有请求排一条队，相邻两次至少隔 2 秒。并发发三四个"看起来更快"，实际是被风控一起拦。
- **错误翻译**：`-352/-412/-509` 对模型毫无意义，翻成"被风控拦了/请求太频繁"它才知道该跳过而不是改参数重试。

## 4. "空是结果不是故障"

字幕这条最容易把模型带进坑：CC 字幕要 UP 上传，AI 字幕要登录。所以 `subtitle()` 的返回值有三种空——没轨道、下载失败、内容为空——全部走 `{ empty: true, reason }`，工具层回一句"没有字幕，按跳过处理"。

章程里对应写死一条：**空就是结果，禁止反复试**。实测那轮有 3 条没字幕，子代理直接在报告末尾写了"因无字幕跳过 3 条"，没有纠缠。

## 5. 额度只在成功时扣

原项目的缺陷是"触发即扣额度"，于是接口抽风的时候额度被烧光、当天再也跑不了。这里的规则：

- 自动轮 + `ok === true` 才 `dayRounds += 1`；
- 手动轮永远不扣（手动是人在旁边看着，不该占自动额度）；
- `lastRunAt` 两种都更新，否则手动刚跑完，定时器立刻又跑一轮。

失败也要写报告（"本轮失败：原因"），因为失败同样花了 token——不留痕就没人知道钱去哪了。

## 6. 播报的气泡

第一版按行切气泡，结果"一句话 + 它自己的链接"被拆成两个气泡，链接孤零零挂在最后。改成：**只有链接的行并回上一句**，再按 `maxBubbles` 收尾。这类小规则必须写成纯函数并单测，否则下次调 prompt 时又会退回去。

## 7. 这一轮的实测数字

- 接口层真机冒烟：popular / 搜索（wbi）/ view / player / reply 五个通；
- 一整轮：约 35 秒、15 次工具调用、挑中 2 条、花费两份模型调用（阅稿 + 播报）；
- `### BV` 行数 = `seen.json` 新增条数 = 播报里提到的条数，三处对得上。
