# 部署手册 · 腾讯云轻量服务器

> 适用：P2e（M6）上云部署。对应计划 ADR：systemd 常驻 + 密钥上云（EnvironmentFile）。
> 前提：服务器 2G 内存即可；项目零 npm 依赖，**服务器上不需要任何 install**。

## 1. 服务器装 Node 18+

```bash
# Ubuntu/Debian（腾讯云轻量默认镜像）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo bash -
sudo apt-get install -y nodejs
node -v   # ≥ 18 即可
```

CentOS/OpenCloudOS 换用 yum 对应源；或直接下载官方二进制包解压到 /usr/local。

## 2. 代码上云

本机执行（排除运行数据与密钥，它们不上云）：

```bash
rsync -av --exclude data --exclude .env --exclude logs --exclude backups \
  ~/Workspaces/WhaleGirl/ user@服务器IP:/opt/whale-girl/
```

也可在服务器 git clone（私有仓库需配 deploy key）。**注意：data/ 不随代码上云**——云端记忆从零开始；如需迁移本地记忆，单独 `rsync data/`（做完这步前别启动服务写入）。

## 3. 密钥上云（ADR：只在 /etc，root 600）

服务器上创建 `/etc/whale-girl.env`，内容从本地 `.env` 复制这几类：

```
WG_DEEPSEEK_API_KEY=sk-...
WG_DEEPSEEK_BASE_URL=https://sub.geiliapi.com/v1
WG_DEEPSEEK_CHAT_MODEL=gpt-5.6
WG_TAVILY_API_KEY=tvly-...
WG_BILI_SESSDATA=...
WG_BILI_BILI_JCT=...
WG_BILI_DEDE_USER_ID=...
WG_BILI_BUVID3=...
WG_BILI_MID=...
WG_ADMIN_TOKEN=...
```

```bash
sudo chmod 600 /etc/whale-girl.env && sudo chown root:root /etc/whale-girl.env
```

规则：**密钥只活在这个文件里**；项目目录的 `.env` 不上传；`config.json` 的 key 字段保持留空。

读取优先级是 `WG_* 环境变量 > config.json > config.example.json`（`src/config.js`）。所以 env 里除了密钥，**不要放任何"默认值"**——模型名、provider、超时、开关这类东西一旦写进 env，config.json 就失效了，改配置会"看起来没反应"（2026-11-01 踩过：env 里一行 `WG_ACTIVE=deepseek` 让切换 provider 全部无效）。

env 只留这几类：

```
WG_DEEPSEEK_API_KEY / WG_ZHIPU_API_KEY / WG_CUSTOM_API_KEY   各 provider 的 key
WG_TAVILY_API_KEY                                             搜索
WG_BILI_*                                                     B站 cookie
WG_ADMIN_TOKEN                                                管理端令牌
```

**换模型只改 config.json，保存即生效**（热加载，不用重启）：

```jsonc
"active": "deepseek",                      // 切 provider
"providers": { "deepseek": { "chatModel": "deepseek-flash" } }  // 切模型
```

改完 `curl -s 127.0.0.1:8787/api/health` 一眼能看见 `provider` / `model` 是否已切换。只有改 env（密钥）或改代码才需要 `systemctl restart whale-girl`。

`WG_ADMIN_TOKEN` 是网页管理端的管理员令牌（`openssl rand -hex 24` 生成）：设置后打开 `/login` 输入它获得管理员权限；不登录的访客只能看（记忆/调参/插件三页只读）和聊天。**公网部署前必须设置**，不设则管理接口无鉴权（仅限本机/隧道使用）。

## 4. systemd 常驻

`/etc/systemd/system/whale-girl.service`：

```ini
[Unit]
Description=WhaleGirl 蓝色小肥鱼
After=network-online.target

[Service]
Type=simple
User=你的用户名
WorkingDirectory=/opt/whale-girl
EnvironmentFile=/etc/whale-girl.env
ExecStart=/usr/bin/node server.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now whale-girl   # 开机自启 + 立即启动
journalctl -u whale-girl -f              # 实时日志（stdout 进 journald，自动轮转）
```

常用运维：

```bash
sudo systemctl restart whale-girl        # 改代码后重启
sudo systemctl status whale-girl         # 状态
```

热加载在云上同样生效：改 config.json、人设不用重启；但改 /etc/whale-girl.env 后需 daemon-reload + restart 才重读。

## 5. 访问方式与鉴权（安全底线）

服务绑定 `127.0.0.1`，现阶段用 SSH 隧道：

```bash
# 本地 Mac 执行，然后浏览器开 http://127.0.0.1:8787
ssh -L 8787:127.0.0.1:8787 user@服务器IP
```

**管理员登录**：`/etc/whale-girl.env` 里设置 `WG_ADMIN_TOKEN`（`openssl rand -hex 24` 生成）后，打开 `/login` 输入令牌即管理员；不登录的访客只能看（记忆/调参/插件三页只读）和聊天。服务端在 handle() 入口统一拦：访客放行 GET 静态页与读接口、聊天，其余写操作一律 401。

> **2026-11-01 起改为公网 HTTPS 反代**（下方 5.1 起为准）；隧道方案保留给管理端排障用。

### 5.1 公网 HTTPS 反代

服务仍绑 `127.0.0.1:8787`，公网入口由服务器上的 nginx 反代，**8787 不对公网开放**。

- 站点配置：`/www/server/panel/vhost/nginx/html_<IP>.conf`（宝塔生成的站点文件，内容已改成反代）
- 80 → 301 到 443；443 是 `default_server` + `server_name _`——**纯 IP 访问时浏览器不发 SNI**（RFC 6066 禁止 IP 字面量进 SNI），没有 default_server 就会落到宝塔的兜底站，表现为 `/api/*` 全 404
- 证书：`/etc/whale-girl/ssl/{fullchain,privkey}.pem`，自签，`CN=服务器IP` 且 **SAN 必须含 `IP:服务器IP`**（Chrome 不看 CN），10 年有效

反代关键配置（SSE 三行少一行，聊天就会憋住后一次性吐出来）：

```nginx
server {
    listen 80 default_server;
    listen [::]:80 default_server;
    server_name _;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl default_server;
    listen [::]:443 ssl default_server;
    http2 on;                     # nginx < 1.25.1 写成 listen 443 ssl http2;
    server_name _;

    ssl_certificate     /etc/whale-girl/ssl/fullchain.pem;
    ssl_certificate_key /etc/whale-girl/ssl/privkey.pem;
    ssl_protocols TLSv1.2 TLSv1.3;

    client_max_body_size 20m;

    location / {
        proxy_pass http://127.0.0.1:8787;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_buffering off;      # SSE 必关
        proxy_cache off;
        proxy_read_timeout 3600s;
    }
}
```

签证书：

```bash
sudo mkdir -p /etc/whale-girl/ssl
sudo openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
  -keyout /etc/whale-girl/ssl/privkey.pem \
  -out /etc/whale-girl/ssl/fullchain.pem \
  -subj "/CN=服务器IP" \
  -addext "subjectAltName=IP:服务器IP" \
  -addext "keyUsage=critical,digitalSignature,keyEncipherment" \
  -addext "extendedKeyUsage=serverAuth"
sudo chmod 600 /etc/whale-girl/ssl/privkey.pem
```

验收：

```bash
curl -sk -o /dev/null -w 'https %{http_code}\n' https://服务器IP/api/health   # 200
echo | openssl s_client -connect 服务器IP:443 2>/dev/null | openssl x509 -noout -subject -ext subjectAltName
curl -s -o /dev/null -w 'http %{http_code} -> %{redirect_url}\n' http://服务器IP/   # 301
```

客户端信任：把 `fullchain.pem` 导入系统钥匙串并设成「始终信任」。注意 **curl 不读钥匙串**（Homebrew 版用自带的 CA bundle，系统版用静态 `/etc/ssl/cert.pem`），命令行要显式 `curl --cacert fullchain.pem`，否则永远报 self signed。

### 5.2 宝塔面板托管 nginx 的两个坑

1. **站点配置会被面板重写**：在面板里对该站点做任何操作（改配置、切 SSL、开防跨站）都会整份重新生成，手写的反代直接消失。改 nginx 一律 SSH 改文件 + `nginx -t` + `nginx -s reload`，别用面板界面。
2. **自定义证书会被清理**：把证书放 `/www/server/panel/vhost/cert/<名字>/` 下，面板的证书同步会当成野文件清掉（实测几分钟内目录被清空，nginx 只是靠内存里的旧证书硬撑，reload 就炸）。一律放 `/etc/whale-girl/ssl/`。

面板自己的端口（`/www/server/panel/data/port.pl`，如 33579）默认对公网开放，SSL 用的是面板自签证书，浏览器会提示"不安全"。**别信任它那张证书**（宝塔默认证书的私钥镜像里预置，人人都有），正确做法是收进口子：

```bash
# 1) 云控制台防火墙删掉面板端口，只留 22 / 80 / 443
# 2) 本地开隧道访问
ssh -L 33579:127.0.0.1:33579 -i <key> user@服务器IP
# 3) 浏览器开 http://127.0.0.1:33579（走隧道前先关掉面板 SSL，否则证书和 127.0.0.1 对不上）
```

### 5.3 备案与域名

大陆机房：**未备案域名**不能解析到 80/443 对外服务（运营商侧拦），纯 IP 访问不受影响。备案期间就按 5.1 这套自签 + IP 跑；备案通过后改两行即可切换，不用重开端口：

- `server_name _` → `server_name 你的域名 www.你的域名`
- 证书换成正式证书（腾讯云免费 DV 走 DNS 验证，**不需要备案就能提前签**，别等最后一天）

### 5.4 数据目录与记忆迁移

- 运行数据全在 `/opt/whale-girl/data/`：`memory/<sessionId>.json`（按会话分文件的对话与事实）、`mood.json`、`bili/{state,seen,notified,history,out,digest}`
- `data/` 在 `.gitignore` 里，**CI 部署的 tar 包不含它**，所以每次发布都不会动云端记忆；反过来也意味着**换机器/首次上云必须手工搬**
- 迁移（一次性）：

```bash
# 先备份服务器现有 data
ssh user@服务器IP 'sudo cp -a /opt/whale-girl/data /www/backup/whale-data-$(date +%Y%m%d-%H%M%S)'
# 再镜像本地
rsync -a --delete data/ user@服务器IP:/opt/whale-girl/data/
ssh user@服务器IP 'sudo systemctl restart whale-girl'
```

- **记忆是按会话分文件的**：前端每个浏览器在 localStorage 里存随机 `sessionId`（`public/index.html`），文件搬上去但 id 对不上等于没搬。要让某个浏览器接上迁移的记忆，控制台执行一次：

```js
localStorage.setItem('whale_session', '<要接上的 sessionId>'); location.reload();
```

页面打开时会用 `GET /api/memory?sessionId=...` 把最近 20 轮旧对话铺回界面（**纯读接口，不调模型**），所以刷新后不是空白页。

## 6. 远程调试

- **状态一览**：`curl -b cookie.jar https://…/api/debug/state`（管理员专属）——内存/uptime/各插件状态/data 文件大小/最近日志路径，远程排障第一入口。
- **Node inspector**（需要断点/查内存时）：

```bash
# 服务器：临时给 service 加 --inspect（绑定 127.0.0.1，用完还原）
sudo systemctl edit whale-girl   # 写入：
# [Service]
# Environment=NODE_OPTIONS=--inspect=127.0.0.1:9229
sudo systemctl restart whale-girl

# 本地 Mac：隧道 + Chrome DevTools 打开 chrome://inspect
ssh -L 9229:127.0.0.1:9229 user@服务器IP

# 用完还原：删掉 override，daemon-reload + restart
```

- `journalctl -u whale-girl -f` 看实时日志；`logs/server-*.log` 按次留存。

## 7. 更新发布（CI/CD）

``.github/workflows/deploy.yml` 已就位（2026-10-30 全链路跑通）：push 到 main → 跑 `npm test` → 通过后 **tar 打包产物 scp 直传服务器**（服务器在国内，直连 GitHub clone 不可靠，故不走服务器侧 git pull）→ 解包到 `/opt/whale-girl` → `systemctl restart` → 探活 `/api/health`，连续 5 次失败自动回滚上一版包并重启。服务器首次部署无需手工 clone，脚本自动处理；每一步失败都会以 GitHub 注解形式报告原因。

**部署不会碰的三样东西**（都在仓库外或在 `.gitignore` 里，tar 包里没有）：`/opt/whale-girl/data/`（记忆与运行数据）、`/opt/whale-girl/config.json`（运行时配置，服务器那份才是权威）、`/etc/whale-girl.env`（密钥）。换句话说，**换机器时这三样要手工搬**，其余交给 CI。

**服务器一次性准备**：

```bash
# 1) 服务器上生成只读 deploy key，公钥加到 GitHub 仓库的 Deploy keys
ssh-keygen -t ed25519 -f ~/.ssh/whalegirl_deploy -N ''
cat ~/.ssh/whalegirl_deploy.pub
# 配置 ~/.ssh/config 让 github.com 走这把 key

# 2) 仓库 Settings → Secrets → Actions 添加：
#    DEPLOY_SSH_KEY = whalegirl_deploy 私钥全文
#    DEPLOY_HOST    = 服务器 IP
#    DEPLOY_USER    = SSH 用户（需免密 sudo systemctl restart whale-girl）
#    sudo visudo 加一行：DEPLOY_USER ALL=(root) NOPASSWD: /usr/bin/systemctl restart whale-girl
```

之后正常 `git push origin main` 即完成发布；失败的推送不会部署（测试先拦一道），部署后探活失败自动回滚。

单人项目不做 PR 预览与 staging：分支即 main，测试过了才允许 push（本地先 `npm test` 再 push）。

## 8. 云上特有注意点

1. **B站风控更严**：数据中心 IP + 登录态 cookie 异地使用，评论/动态进审核概率更高，甚至可能触发重新登录。对策：互动额度收紧（features.bili.interact）观察几天；若全线被审，可分工——本地 Mac 跑 B站互动，云端跑对话与网页。
2. **面板入口**：/settings 参数面板走隧道访问，写回的是云端 config.json（保注释）。
3. **时区**：B站活跃时段（activeWindows）按服务器本地时间判断，建议 `sudo timedatectl set-timezone Asia/Shanghai`，否则时段判断会偏。
4. **IPv6 黑洞**：服务器常没有 IPv6 出口，而上游 API 域名（Cloudflare 系）带 AAAA 记录。Node 的 `fetch` 会先试 v6，直接 `fetch failed`，日志里表现为 `[chat] 失败（network）`。修法（已生效）：

```ini
# /etc/systemd/system/whale-girl.service.d/ipv4.conf
[Service]
Environment=NODE_OPTIONS=--dns-result-order=ipv4first
```

```bash
sudo systemctl daemon-reload && sudo systemctl restart whale-girl
```

5. **上游网关会整片挂**：中转站（OpenAI 兼容代理）出 `503 ROUTING_UNAVAILABLE` 时，同一网关下多个模型一起不可用，别怀疑自己的部署。判断办法：直接 `curl` 上游 `/v1/models` 看首字节和状态码，超过 2 秒或报错就换 provider（`config.json` 的 `active` 一行）。官方 `api.deepseek.com` / `open.bigmodel.cn` 在国内服务器上首字节约 50~150ms。
6. **B站互动只认落库记录**：报告里的「互动：」行由 `interactLog` 回填（`src/features/bili/runner.js` 的 `applyInteractionFacts`），模型没真正调用写工具就只会显示"无"。排查互动是否生效，看 `data/bili/state.json` 的 `interactLog`，别信报告文字。

## 10. 常见问题

| 现象 | 处理 |
|---|---|
| 启动报 port 占用 | `ss -ltnp | grep 8787` 找到占用进程，或改 config.json 的 server.port |
| key 未生效 | `systemctl show whale-girl | grep Environment` 确认 EnvironmentFile 被读入；改了 env 文件后必须 daemon-reload + restart |
| B站接口 -412/-352 | 服务器 IP 风控：降低 interact 额度与 dailyQuota，或回本地跑互动 |
| 日志想落文件 | journald 够用；确要文件可在 service 里加 StandardOutput=append:/opt/whale-girl/logs/run.log（目录需存在） |
